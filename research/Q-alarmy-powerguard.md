# 알라미는 전원 메뉴를 어떻게 닫나 (11-27 Leader 조사)

대상: 알라미 26.43.0(droom.sleepIfUCan), 사용자 폰에서 꺼낸 앱 파일. 앱 설정 파일과 코드 구조만 읽었고, 알라미 코드를 우리 앱에 옮기지 않아요. 방식만 참고해요.

## 결론

알라미는 **접근성 신호로 전원 메뉴를 알아채지 않아요.** 울림 화면이 **초점을 잃는 순간**(무엇이든 위에 뜨면)을 신호로 써요. 그다음 접근성 서비스가 **홈 → 뒤로**를 0.1초 간격으로 **세 번** 보내요.

## 흐름

| 순서 | 무엇이 | 하는 일 |
|---|---|---|
| 1 | 울림 화면(`feature.alarmring.AlarmActivity`) | `onWindowFocusChanged(false)`가 오면 울림 화면 뷰모델에 알려요. 전원 메뉴, 알림 창, 다른 앱 창 등 모든 초점 잃음이 해당돼요 |
| 2 | 전원 끄기 방지 처리(use case) | 설정에서 '전원 끄기 방지'가 켜져 있으면 채널에 신호 하나를 넣어요 |
| 3 | 접근성 서비스(`com.alarmy.shutdownblocker.feature.main.ShutdownBlockerService`) | 서비스가 켜질 때부터 이 채널을 듣고 있어요. 신호가 오면 아래 4번을 해요 |
| 4 | 닫기 반복 | 0.1초 기다림 → `GLOBAL_ACTION_HOME` → `GLOBAL_ACTION_BACK`. 이것을 **3번** 해요(약 0.3초) |
| 5 | 마무리 | 막은 횟수를 하나 올리고 'PreventoffCheatingDetected' 기록을 남겨요. 0.4초 쉬어요. 이 뒤에 또 초점을 잃으면 1번부터 다시 해요 |

- 서비스의 `onAccessibilityEvent`는 **비어 있어요**(아무것도 안 함). 창 이름(SamsungGlobalActionsDialog 등)을 확인하지 않아요.
- 홈을 보낸 뒤 울림 화면을 다시 앞으로 부르는 코드는 이 흐름에 없어요. 알람이 울리는 중이라 울림 서비스가 화면을 다시 띄우는 것으로 보여요(확인 필요).

## 접근성 설정 비교

| 항목 | 알라미 | 우리(`core/alarm/src/main/res/xml/power_guard_service.xml`) |
|---|---|---|
| 받는 신호 | 창 바뀜(typeWindowStateChanged) | 같음 |
| 화면 내용 읽기(canRetrieveWindowContent) | 켬 | 끔 |
| 플래그 | 기본 + 뷰 ID 알림 + 여러 창 정보(0x51) | 없음 |
| 신호 모으는 간격(notificationTimeout) | 50ms | 0 |
| 실제 판단 | 울림 화면의 초점 잃음 | 접근성 신호의 창 이름 |

## 우리와 다른 점, 우리에게 주는 뜻

1. **알아채는 방법**: 우리는 삼성 전원 메뉴 창 이름이 맞아야 움직여요. 알라미는 울림 화면이 가려지기만 하면 움직여서 기기와 OS 판에 덜 흔들려요.
2. **순서**: 우리는 뒤로 → 0.2초 홈 → 0.5초 화면 다시 열기, 한 번만 해요. 알라미는 홈 → 뒤로를 0.1초마다 세 번 보내요.
3. **다시 하기**: 알라미는 0.4초 뒤 또 가려지면 다시 해요. 우리 d64ab49(창이 사라질 때까지 다시 닫기)와 뜻이 비슷해요.
4. 미션 중 화면도 같은 방식이 필요해요(우리 범위는 울림, 다시 울림 쉬는 중, 미션 중. 결정 197).

## 폰 확인

- 11-27 13:32 S24+에서 알라미 퀵 알람(소리 0, 진동)을 울리고 측면+볼륨 아래(adb 1.5초)로 전원 메뉴를 열었어요. 13:32:07에 '휴대전화 옵션' 창이 맨 앞에 뜬 직후 S24+가 PC USB 목록에서 통째로 사라져서 그 뒤는 못 봤어요. 원인은 아직 몰라요(폰 꺼짐, 다시 시작, 케이블 중 하나).
