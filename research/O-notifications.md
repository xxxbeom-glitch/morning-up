## 2. 알라미 알림 목록
- 폰 확인: [리서치 5], 2026-11-26 11:04~11:22, Z플립5, 알라미 26.43.0(프로 구독 상태). 시험 알람 두 번을 소리 없이 울렸어요(앱 안 볼륨 0, 알람 소리 1, 음악 소리 0, 지킴이). 캡처는 `docs/exports/tsk-216/`(134~144). 알림 창 캡처는 다른 앱 알림을 잘라 냈어요.
- 알림 통로(채널): 알라미가 이 폰에 만든 통로는 13개예요. 소식, 무료 체험 끝, 취침 알림 2개, 캠페인, 첫 설정 진행, 알람 미리 알림, 사전 기상 감지, 수면 측정 중, 오늘의 날씨, 리포트, **다음 알람**, **알람 상태**. 알람 흐름에 쓰는 것은 굵게 쓴 두 개뿐이고, 나머지는 홍보, 날씨, 수면 기능용이에요.

- 흐름 요약: 알라미는 **울리는 중, 미루는 중, 확인하는 중**에만 못 지우는 알림 하나를 띄워요. 그 사이 기다림이나 놓침은 알리지 않아요. 앞에 늘 전체 화면이 있어서 알림은 거의 '앱이 돌고 있다'는 표시예요.
- 알람 흐름 밖의 통로(날씨, 취침, 리포트, 소식, 캠페인)는 이번에 뜬 것이 없어요. 통로 이름만 확인했어요.

## 3. 떠야 하는데 안 뜨는 것, 알라미와 비교
| 상황 | 알라미 | 우리(1절) | 판단 |
|---|---|---|---|
| 다음 알람 늘 보이기 | 고급설정에서 켜면 A(처음엔 꺼짐) | 없음 | **추가 후보(낮음).** 설정 한 줄, 처음엔 꺼짐. 쉬는 중이면 '(건너뜀)'만 쓰지 말고 **실제 다음 울림 시각**을 써요(알라미 방식은 TSK-215의 헷갈림과 같은 문제) |
| 울리는 중 | B | 1~4 | 같음. 우리는 누르면 울림 화면이 열려 더 나아요 |
| 다시 울림 사이 쉬는 중 | (미루기 C) | 5 | 같음 |
| 끈 뒤 확인 기다림 | 알림 없음 | 6, 7, 8 | 우리가 더 많이 알려요. 결정 145, 146대로 둬요 |
| 확인할 때 | D + 전체 화면 | W2, W3 화면 + 3번 알림 | 같은 흐름(결정 178에 맞음) |
| 놓친 알람 | 알림 없음 | 11 | 우리만 있어요. 두는 게 맞아요. **누르면 아무것도 안 열리는 것은 고쳐요**(4절) |
| 배터리 제한 경고 | 알림 없음(설정 '알람 울림 최적화'에 모음) | 12 | 우리만 있어요. 그대로 둬요 |
| 잠자리(취침 시간) 알림 | 통로 있음(이번엔 안 뜸) | 없음 | 잠들기 탭과 어울리는 2차 후보. 지금은 넣지 않음 |
| 아침 날씨 알림 | 통로 있음 | 없음 | 넣지 않음(날씨는 홈, W1) |

- **결론: 우리 앱에 빠진 알림은 없어요.** 고칠 것은 4절 두 가지(ID 5 겹침, 놓친 알람 알림을 눌러도 안 열림)예요. 새로 넣을 만한 것은 '다음 알람 늘 보이기' 하나(선택, 처음엔 꺼짐)예요.

## 4. 코드에서 본 작은 문제
- **ID 5가 겹쳐요.** 배터리 알림(`BatteryReminder.NOTIFICATION_ID = 5`)과 예전 미션 비상구 알림(`RingNotifications.ESCAPE_NOTIFICATION_ID = 5`)이 같은 번호예요. 알람이 끝날 때 `cancelRinging`이 5번을 지워서, 밤 9시 배터리 알림이 떠 있으면 다음 날 아침 알람이 끝날 때 같이 사라져요. 크게 해롭지는 않지만 번호를 나누는 게 좋아요(개발 몫).
- **놓친 알람 알림(11)은 눌러도 아무것도 안 열려요**(`setContentIntent` 없음). 홈을 열게 하면 좋아요.
- 11-26 사용자 지시 1번(미션 포기를 알림이 아니라 화면으로)이 들어가면 9, 10번은 바뀌어요(TSK-208 쪽).
