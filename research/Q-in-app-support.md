## 4. 레시피

### 4-1. 0단계: 메일로 보내기 (서버 없음)

1. 설정 '의견 보내기' 이름을 '문의하기'로 바꾸고 작은 화면을 하나 둬요: 종류(버그, 문의, 제안), 자주 겪는지(버그일 때만), 내용, **'앱 기록 같이 보내기'** 스위치(버그면 켜짐).
2. 보내기를 누르면 앱 기록 파일 하나를 만들어요(4-3). 위치는 `cacheDir/support/`.
3. `FileProvider`로 파일 주소를 만들고 `Intent.ACTION_SEND`(받는 주소, 제목, 본문, `EXTRA_STREAM`, `FLAG_GRANT_READ_URI_PERMISSION`)로 메일 앱을 열어요. 받는 주소는 사업자 대표 메일(코드 상수로, 이 문서엔 안 적음).
4. 본문 첫 줄에 문의 번호(설치 번호 앞 8자 + 날짜)를 넣어 답장할 때 찾기 쉽게 해요.
5. 메일 앱에서 사용자가 첨부와 내용을 **직접 보고** 보내요. 지금 이미 하는 '기기, 안드로이드, 앱 버전, 꺼진 권한' 본문(`settings_feedback_body`)은 그대로 살려요.

README 5번 규칙대로 해요. **아래는 설계안이고 아무것도 만들지 않았어요.**

| 2 | 로그인: 지금 켜진 건 Google 하나. 우리는 로그인 없는 앱이라 **익명 로그인(Anonymous)** 을 켜야 해요. 프로젝트 전체 설정이라 **사용자 동의 필요** | 3번 |

### 4-3. 앱 기록 파일에 넣을 것 (알람 안 울림 원인 찾기용)

이미 있는 것: `DiagnosticLog`(Room `diagnostic_log`, 최근 2000줄: 예약, 울림, 꺼짐, 놓침, 대신 예약, 화면 켜기 건너뜀 등)와 `AlarmDiagnostics.record()`.

| 넣을 것 | 어디서 | 왜 |
|---|---|---|
| 진단 기록 최근 7일 | `DiagnosticLog.entries()` | 예약 → 울림 → 꺼짐 흐름이 끊긴 곳 |
| 앱이 죽은 이유 최근 10건 | `ActivityManager.getHistoricalProcessExitReasons()`(API 30+) | 배터리 최적화나 메모리로 꺼졌는지(`REASON_LOW_MEMORY`, `REASON_USER_REQUESTED` 등) |
| 권한, 상태 | 정확한 알람 허용, 알림, 다른 앱 위, 접근성, 배터리 최적화 제외 여부, 방해 금지 상태, 앱 대기 버킷(`UsageStatsManager.getAppStandbyBucket()`) | '권한은 켰는데 안 울림'인지 |
| 다음 예약 | `AlarmManager.getNextAlarmClock()` | 실제로 예약이 걸려 있는지 |
| 기기 | 제조사, 모델, 안드로이드 버전, 앱 버전, 절전 모드 켜짐 | 기기별 문제 |
| 알람 설정 요약 | 알람마다 시각, 반복, 켜짐, 미션 종류, 볼륨 | 설정 문제인지 |

형식: `summary.txt`(사람이 읽는 요약) + `log.csv`(진단 기록)를 zip 하나로. 보통 100KB 안쪽이에요.

**넣지 않을 것(개인정보):** 알람 이름(사용자가 쓴 글이라 이름, 약 이름 같은 개인정보가 들어갈 수 있음 → '알람 3'처럼 바꿔 적기), 날씨용 위치 좌표, 설치된 다른 앱 목록, 연락처, 메일 주소(0단계는 메일 앱이 알아서 붙임).
