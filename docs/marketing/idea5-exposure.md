# 아이디어 5: 출시 노출 설계 (브랜드 사이트, SNS, SEO, AEO, GEO)

11-23 [마케팅 1] 작성. 11-23 사용자가 추천안을 승인했어요("그렇게 해", Leader 전달). 실제 계정 만들기, 글 올리기, 사이트 배포는 하지 않았어요.

## 확정 (11-23 사용자 승인)

| 항목 | 확정 내용 |
|---|---|
| 브랜드 사이트 | 이 무료 앱 하나만 소개하는 한 장 사이트. 구성은 한 장 소개 + 개인정보처리방침 + 자주 묻는 질문 |
| 올릴 곳 | GitHub Pages. 도메인은 나중에 정함 |
| 사이트 이름 | 앱 이름이 미정('깨'/GGAE 후보)이라 앱 이름이 정해진 뒤 정함 |
| 첫 SNS | 인스타그램 하나 (자세한 건 아이디어 7에서) |
| 나중에 정할 것 | 스토어 글의 '광고 없음' 문구, 사이트에 사업자 정보를 넣을지. 사업자 정보를 넣게 되면 어떤 항목을 넣을지는 Leader가 사용자에게 먼저 물어요 |
원문(`docs/ideas-11-22.md` 5번): "출시 고려했을 때 브랜드 사이트 구축, SNS 포스팅 마케팅, AEO, SEO, GEO 등의 노출 방식 설계. 중요한 건 돈을 당장 버는 것보다 잠을 깨야만 하는 자들을 위해 무료로 풀고 가볍게 접근한다는 것. 핵심은 설치율, 유지율, 사용자 확보."

## 결론 (먼저 읽을 것)

- **방향은 맞아요.** 무료, 가볍게, 설치율과 유지율 중심은 1인 개발 알람 앱에 가장 현실적인 길이에요.
- 다만 **혼자, 돈 없이 할 때 효과 순서는 '플레이 스토어 안 검색(ASO) > 유지율 > 사이트 한 장 > SNS > SEO, AEO, GEO'** 예요. 처음 설치의 대부분은 플레이 스토어 안에서 '알람'을 검색한 사람에게서 나와요. 사이트, AEO, GEO는 효과가 몇 달 뒤에 천천히 나와요.
- 알람 앱은 **유지율이 곧 마케팅**이에요. 아침에 한 번이라도 안 울리면 바로 지우고 별점 1점을 줘요. 그래서 '울림 실패 0'과 첫날 경험이 어떤 홍보보다 먼저예요.
- 브랜드 사이트는 **한 장짜리 랜딩 + 개인정보처리방침 + 자주 묻는 질문(FAQ)** 이면 충분해요. 무료로 만들 수 있고, 어차피 개인정보처리방침 주소가 필요해서 같이 해결돼요.
- AEO와 GEO는 따로 큰일을 할 필요 없이, **사이트 FAQ를 '질문 → 바로 답' 모양으로 쓰는 것**과 **스토어, 사이트, SNS에서 앱 소개 문장을 똑같이 쓰는 것**만으로 기본은 돼요.

## 1. 사용자 생각에 대한 피드백

| 구분 | 내용 |
|---|---|
| 좋은 점 | '무료로 가볍게'가 분명해서 메시지가 쉬워요. 알라미 같은 앱이 유료 구독과 강한 미션으로 가는 것과 반대 자리라, "덜 정신없는 무료 알람"이라는 한 줄로 설명돼요 |
| 좋은 점 | 매출 대신 설치율, 유지율을 핵심으로 잡은 것이 맞아요. 출시 초기에 볼 숫자가 분명해야 무엇을 고칠지 알 수 있어요 |
| 빠진 점 1 | **플레이 스토어 검색(ASO)이 목록에 없어요.** 돈 없이 할 때 가장 큰 설치 통로예요. 스토어 제목, 짧은 설명, 스크린샷이 사이트보다 먼저예요 |
| 빠진 점 2 | **리뷰와 별점 관리가 없어요.** 별점이 낮으면 검색 순위와 설치 전환이 같이 떨어져요. 리뷰에 답글을 다는 것만으로도 효과가 있어요 |
| 빠진 점 3 | **유지율을 올리는 앱 안 장치가 없어요.** 첫 알람을 설정하게 돕는 온보딩, 연속 기록(W1), 다시 잠들기 방지가 사실상 유지율 마케팅이에요. 이미 만든 것이라 '마케팅 문구'로 꺼내 쓰기만 하면 돼요 |
| 빠진 점 4 | **"왜 우리 앱인가" 한 줄이 아직 없어요.** 이건 아이디어 9번에서 정해요. 이 한 줄이 정해져야 스토어 글, 사이트, SNS가 같은 말을 해요 |
| 조심할 점 | SEO, AEO, GEO를 처음부터 크게 하면 시간 대비 효과가 낮아요. 1인이 블로그 글을 꾸준히 쓰기 어렵고, 검색 엔진과 AI는 새 사이트를 잘 믿지 않아요. **기본만 깔고 출시 뒤 반응을 보며 늘리는 것**을 추천해요 |

### 혼자, 돈 없이 할 때 우선순위

| 순서 | 할 일 | 이유 |
|---|---|---|
| 1 | 알람이 반드시 울리게 (개발, 아이디어 6) | 한 번 실패하면 삭제와 별점 1점. 모든 마케팅이 무너져요 |
| 2 | 플레이 스토어 글과 그림 (ASO) | 설치의 대부분이 스토어 검색에서 와요. 무료이고 바로 효과가 나요 |
| 3 | 리뷰 답글과 별점 요청 타이밍 | 별점이 검색 순위와 전환율에 영향을 줘요 |
| 4 | 한 장짜리 브랜드 사이트 + FAQ | 개인정보처리방침 주소 겸용. SEO, AEO, GEO의 바탕이 돼요 |
| 5 | SNS 브랜드 계정 (아이디어 7) | 꾸준히 할 수 있는 만큼만. 짤 한 종류로 시작 |
| 6 | SEO 글, 커뮤니티 답변 (아이디어 8) | 효과는 늦지만 오래가요. 출시 뒤 여유가 생기면 |

## 2. 노출 채널별 설계

### 2-1. 용어 쉽게 풀기

| 이름 | 쉬운 뜻 | 우리에게 해당하는 곳 |
|---|---|---|
| ASO (앱스토어 최적화) | 플레이 스토어 안에서 '알람'을 검색했을 때 우리 앱이 잘 보이고, 눌렀을 때 설치하게 만드는 일 | 구글 플레이 |
| SEO (검색 엔진 최적화) | 구글, 네이버에서 검색했을 때 우리 사이트가 위에 나오게 하는 일 | 브랜드 사이트 |
| AEO (답변 엔진 최적화) | 검색 결과 맨 위 'AI 요약'이나 '추천 답변' 상자에 우리 내용이 뽑혀 나오게 하는 일. 질문에 바로 답하는 글이 핵심이에요 | 구글 AI 개요, 네이버 AI 브리핑 |
| GEO (생성형 AI 검색 최적화) | ChatGPT, Perplexity, 제미나이 같은 AI에게 "잘 깨는 무료 알람 앱 추천해 줘"라고 물었을 때 우리 앱 이름이 나오게 하는 일 | AI 챗봇 |

- 요즘 자료들은 AEO와 GEO를 거의 같은 뜻으로 써요. 둘 다 **"SEO의 연장선"** 이라 기본 원칙(질문에 바로 답하기, 이름을 정확히 쓰기, 구조화된 정보)이 같아요.

### 2-2. 채널별 설계표

| 채널 | 할 일 | 비용 | 효과 나오는 시기 | 우선순위 |
|---|---|---|---|---|
| **플레이 스토어 (ASO)** | 제목(30자 이내)에 앱 이름 + 핵심 단어 하나, 짧은 설명(80자)에 무엇을 하는 앱인지 한 문장, 긴 설명(4000자)에 '알람', '미션 알람', '기상' 같은 단어를 자연스럽게 섞기, 스크린샷 첫 2~3장에 핵심 기능, 출시 뒤 리뷰 답글 | 0원 | 출시 직후부터 | **1** |
| **브랜드 사이트** | 한 장짜리 랜딩(앱 한 줄 소개, 스크린샷, 플레이 스토어 버튼), 개인정보처리방침, FAQ 페이지 | 0원 (도메인을 사면 1년 약 1~3만 원, 없어도 됨) | 사이트 자체 효과는 느림. 개인정보처리방침 주소는 출시에 꼭 필요 | **2** |
| **SNS** | 인스타그램, X, 스레드 중 **하나부터**. 아침 기상 짤, 미션 장면 짧은 영상 (아이디어 7에서 구체화) | 0원 (시간이 비용) | 꾸준히 2~3달 | 3 |
| **SEO** | 사이트 제목과 설명 문구, 구글 서치 콘솔과 네이버 서치어드바이저 등록(무료), FAQ 글. 블로그 글은 출시 뒤 여유가 있을 때 | 0원 | 3~6달 | 4 |
| **AEO** | FAQ를 '질문 → 첫 줄에 바로 답' 모양으로, FAQ 구조화 정보(schema) 넣기 | 0원 | 3~6달, 보장 없음 | 4 (SEO와 같이) |
| **GEO** | 스토어, 사이트, SNS에서 **앱 소개 한 문장을 똑같이** 쓰기, 앱 이름을 정확히 쓰기, 다른 사람이 쓴 언급(리뷰, 커뮤니티 글) 쌓기 | 0원 | 6달 이상, 보장 없음 | 5 |

### 2-3. 플레이 스토어 (ASO) 자세히

규칙 (구글 공식 도움말 기준):
- 제목 30자, 짧은 설명 80자, 긴 설명 4000자.
- **금지**: 키워드 나열(쉼표로 단어만 늘어놓기), "1위", "최고", "인기", "올해의 앱" 같은 순위나 성과 표현, 상 받은 듯한 아이콘. 제목, 아이콘, 글 어디에도 안 돼요. 어기면 등록이 거절되거나 내려갈 수 있어요.
- 구글은 "쓸데없는 키워드는 순위에 도움이 안 된다"고 직접 말해요. 사람이 읽기 좋은 문장 안에 단어를 자연스럽게 넣는 게 맞아요.
- 플레이 콘솔의 **스토어 등록정보 실험**(무료 A/B 테스트)으로 아이콘, 스크린샷, 짧은 설명을 두 가지로 나눠 어느 쪽이 설치가 많은지 볼 수 있어요. 출시 뒤 사용자 수가 조금 쌓이면 써요.
- **맞춤 스토어 등록정보**(최대 50개)로 특정 검색어나 특정 링크로 들어온 사람에게 다른 그림과 글을 보여줄 수 있어요. 처음엔 필요 없고, SNS 캠페인을 할 때 써 볼 만해요.

손님이 보는 글 예시 (앱 이름은 미정이라 비워 둠, 확정 아님):

| 칸 | 예시 A (가벼움 강조) | 예시 B (다시 잠들기 방지 강조) |
|---|---|---|
| 제목 (30자) | `앱 이름: 미션 알람` | `앱 이름 미션 알람 시계` |
| 짧은 설명 (80자) | 수학 한 문제, 단어 하나로 가볍게 잠을 깨우는 무료 알람이에요. | 미션으로 깨우고, 다시 잠들지 않았는지 한 번 더 물어보는 무료 알람이에요. |
| 긴 설명 첫 줄 | 아침마다 알람을 끄고 다시 잠드나요? 앱 이름은 짧은 미션으로 머리를 깨우는 무료 알람이에요. | 알람을 끄고 다시 잠드는 게 문제라면, 앱 이름이 몇 분 뒤 "깨어 있나요?"라고 다시 물어봐요. |

- 긴 설명에 넣을 단어 후보: 알람, 미션 알람, 기상 알람, 아침 알람, 다시 잠들기 방지, 지각 방지, 수학 알람, 흔들기 알람, 날씨.
- 긴 설명에 넣을 기능 (이미 만든 것): Quick Math, Pop Quiz, Drop Words, Shake Shake 미션, 다시 잠들기 방지, 날씨, 연속 기상 기록, 전원 종료 방지.
- '광고 없음'은 출시판에 광고를 넣지 않는다고 확정되면 짧은 설명에 넣을 만한 강점이에요 (**Leader 확인 필요**).

### 2-4. 브랜드 사이트: 한 장으로 충분한가

**충분해요.** 1인 무료 앱은 사이트에서 설치가 거의 나오지 않아요. 사이트의 역할은 세 가지예요.
1. 개인정보처리방침 공개 주소 (출시 필수)
2. "이 앱 믿을 만한가?" 확인용 (검색해 본 사람에게)
3. FAQ를 통한 SEO, AEO, GEO의 바탕

무료로 만드는 방법:

| 방법 | 장점 | 단점 | 추천 |
|---|---|---|---|
| **GitHub Pages** | 무료, 이미 깃 저장소를 쓰고 있어 Claude가 바로 만들 수 있음, 검색 엔진 등록 쉬움 | 주소가 `아이디.github.io` 꼴 (도메인을 사면 바꿀 수 있음) | **추천** |
| Cloudflare Pages | 무료, 빠름, 도메인 연결 쉬움 | 계정이 하나 더 필요 | 2순위 |
| 노션 공개 페이지 | 가장 쉬움, 코딩 없음 | 검색 노출 약함, 디자인 자유도 낮음, FAQ 구조화 정보 못 넣음 | 개인정보처리방침만 급할 때 |

사이트 구성 (한 장 + 두 쪽):

| 쪽 | 내용 |
|---|---|
| 첫 화면 | 앱 아이콘, 한 줄 소개, 플레이 스토어 버튼, 스크린샷 3장 |
| 기능 | 미션 4가지, 다시 잠들기 방지, 날씨, 연속 기록을 짧게 |
| FAQ | "알람이 안 울리면?", "무료인가요?", "어떤 권한이 왜 필요한가요?", "다시 잠들기 방지는 어떻게 동작하나요?" 등 5~8개 |
| 개인정보처리방침 | `privacy-policy-draft.md` 정리본 |

- 사업자 정보(상호, 연락처 등)를 사이트에 넣을지는 **Leader 확인 필요**예요. 플레이 콘솔 판매자 정보와 맞춰야 할 수도 있어요.

### 2-5. SEO, AEO, GEO 기본 설계 (최소한만)

| 할 일 | 하는 법 | 언제 |
|---|---|---|
| 앱 소개 한 문장 고정 | 스토어 짧은 설명, 사이트 첫 줄, SNS 소개를 같은 문장으로. AI가 우리 앱을 한 가지 뜻으로 기억하게 해요 | 아이디어 9 끝난 뒤 |
| FAQ를 질문형으로 | 제목은 사람이 실제로 묻는 말("알람 끄고 다시 자는 거 막는 법"), 첫 줄에 바로 답, 그 뒤 설명 | 사이트 만들 때 |
| 구조화 정보 | FAQ와 앱 정보(SoftwareApplication) 표시를 페이지 코드에 넣기. 구글 '리치 결과 테스트'로 확인 | 사이트 만들 때 |
| 검색 엔진 등록 | 구글 서치 콘솔, 네이버 서치어드바이저에 사이트 등록 (무료) | 사이트 공개 직후 |
| 앱 이름 정확히 | "그 앱", "이 앱" 대신 늘 앱 이름을 써요. AI가 인용하기 쉬워져요 | 늘 |
| 남이 쓴 언급 쌓기 | 리뷰, 커뮤니티 답글(아이디어 8의 안전한 방법), 앱 소개 사이트 등록 | 출시 뒤 |

최신 상황 (11-23 확인):
- **네이버 AI 브리핑**은 2026년 들어 공식 기관 블로그와 네이버 내부 서비스(지식iN, 클립 등) 인용 비중을 늘리고 있어요. 개인 블로그 글이 뽑히기는 점점 어려워져요. 그래서 네이버는 **사이트 등록 + 지식iN 같은 질문 답변 자리**가 현실적이에요.
- **ChatGPT, Perplexity** 같은 AI가 어떤 출처를 인용하는지는 조사마다 결과가 크게 달라요. 레딧 인용이 2026년 8월에 크게 줄었다는 보도도 있고, 출처 목록이 매주 절반 넘게 바뀐다는 조사도 있어요. **"이렇게 하면 AI에 나온다"는 확실한 방법은 없어요.** 그래서 큰 비용을 쓰지 말고 기본만 해 두는 걸 추천해요.
- 대부분의 GEO 자료는 관련 도구를 파는 회사가 쓴 것이라 숫자를 그대로 믿기 어려워요.

## 3. 설치율, 유지율 지표와 무료로 보는 법

| 지표 | 뜻 | 어디서 보나 | 처음 목표(참고) |
|---|---|---|---|
| 스토어 방문 → 설치 전환율 | 스토어 페이지를 본 사람 중 설치한 비율 | 플레이 콘솔 통계, 전환 분석 | 같은 분류 앱 평균과 비교 (콘솔이 보여줌) |
| 설치 경로 | 검색, 둘러보기, 외부 링크 중 어디서 왔나 | 플레이 콘솔 사용자 확보 보고서 | 검색 비중이 크면 ASO가 맞게 된 것 |
| 검색어 | 어떤 단어로 검색해 들어왔나 | 플레이 콘솔 사용자 확보 보고서(검색어) | 스토어 글 고칠 때 참고 |
| 삭제 수, 삭제율 | 설치 뒤 지운 비율 | 플레이 콘솔 통계 | 첫 주 삭제가 많으면 첫날 경험 문제 |
| 1일, 7일, 30일 유지율 | 설치 뒤 며칠째에도 쓰는 비율 | 플레이 콘솔에서 바로 나오는지 **출시 때 확인 필요** (옛 '설치 유지 사용자' 보고서는 없어짐). 안 나오면 '활성 기기 수'와 '삭제 수'로 대략 봐요 | 알람 앱은 7일 유지가 핵심 |
| 비정상 종료, 응답 없음 | 앱이 죽은 비율 | 플레이 콘솔 Android vitals | 구글 기준선 아래 |
| 별점과 리뷰 | 평균 별점, 리뷰 내용 | 플레이 콘솔 평점과 리뷰 | 4.0 이상 유지 |

- **추천: 처음엔 플레이 콘솔 기본 통계만 써요.** 출시 흐름 문서(4번)와 같은 판단이에요. 분석 도구(Firebase 애널리틱스 등)를 넣으면 개인정보처리방침과 데이터 보안 양식을 고쳐야 하고, Firebase 프로젝트는 여러 앱이 같이 쓰는 곳이라 손이 더 가요.
- 앱 안에서 무료로 볼 수 있는 대체 숫자: 연속 기상 기록(W1)이 며칠 이어지는지는 앱 안에만 있어서 밖으로 안 보내요. 필요해지면 그때 정해요.
- 매주 한 번, 같은 요일에 숫자 5개(설치, 삭제, 전환율, 별점, 비정상 종료)를 표 하나에 적는 것만으로 충분해요.
