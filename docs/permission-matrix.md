# 권한 조합별 기대 반응 표 (TSK-177)

11-24 [기획 5] 작성. 근거: 지금 코드(`core/alarm`의 `AndroidPermissionChecker`, `RingNotifications`, `RingService`, `ExactAlarms`, `Receivers`, `BatteryReminder`, `AlarmRescheduler`, `feature/home`의 `PermissionPrompt`, `feature/settings`의 `PermissionPage`), 결정 143(기기 호환성 대책 4개), 결정 145(다시 잠들기 방지), `docs/idea6-device-compat.md`, TSK-177 댓글(삼성 루틴 방해 금지, 배터리 킬 4경우).
**'지금 동작'은 코드에서 읽은 사실, '정할 반응'은 기획 추천이고 사용자 확인 전이에요.** 안드로이드 규칙에서 나온 것 중 폰으로 확인해야 하는 것은 '실기 확인'이라고 적었어요. 사용자에게 물을 것은 맨 아래에 모았어요.
줄 번호(P-, C-, M-, D-, B-)는 QA 체크리스트(TSK-145)로 그대로 옮겨 쓰는 번호예요.

## 결론

1. **7개 권한과 방해 금지, 배터리 킬은 하는 일에 따라 세 묶음이에요.** 조합 결과는 묶음끼리 서로 섞이지 않아서, 128개를 다 보지 않고 '화면 묶음 8가지 + 소리 묶음 줄 + 부가 묶음 줄'로 빠짐없이 덮어요.
2. **가장 위험한 것은 '알림'과 '다른 앱 위에 표시'가 같이 꺼진 경우예요.** 지금 코드는 소리만 나고 화면도 알림도 안 떠서, 끌 방법이 앱을 직접 여는 것뿐이에요.
3. **중간에 끄면 앱이 다시 시작될 수 있어요.** 안드로이드는 알림, 위치 같은 권한을 사용자가 끄면 앱을 닫아요(정확한 알람 권한은 예약까지 지워요). 울리는 중에 끄면 소리가 멈출 수 있어서, 다시 이어 울리는지가 꼭 시험할 줄이에요.
4. **지금 없는 검사가 셋이에요.** 방해 금지가 알람을 막는지, 배터리 '제한'(`isBackgroundRestricted`), 강제 종료 흔적. 결정 143에 있고 TSK-094가 만들어요. 이 표가 그 반응을 정해요.

## 1. 묶는 기준

| 묶음 | 들어가는 것 | 결과에 주는 영향 | 조합을 보는 법 |
|---|---|---|---|
| A. 화면 띄우기 | 알림(N), 다른 앱 위에 표시(O), 전체 화면 알림(F) | 울림 화면이 뜨는지, 알림으로 끌 수 있는지 | 셋이 서로 대신해 주는 관계라 8가지를 모두 봐요(2절) |
| B. 제때 소리 내기 | 정확한 알람(E), 배터리 예외(B), 방해 금지(Z), 배터리 킬 4경우, 음량 0 | 제시각에 울리는지, 소리가 나는지 | 하나씩 따로 영향을 줘요. 여러 개면 영향이 더해져요(3절) |
| C. 부가 | 위치(L), 전원 종료 방지 접근성(P) | 알람 울림에는 영향 없음. 날씨, 미션 중 전원 메뉴 막기만 | 하나씩(4절) |

- 2개, 3개 이상 꺼짐: A 안에서는 8가지 표, A와 B, C 사이는 '각 줄의 결과를 더함'이에요. 예: N과 B가 꺼짐 = 2절 'N만 꺼짐' + 3절 'B 꺼짐'.
- 화면에 보이는 경고(배너)는 한 번에 하나라서, 여러 개 꺼졌을 때 무엇을 보여 줄지는 5절에서 정해요.
- 폰 상태 셋: 화면 꺼짐(잠김), 다른 앱 쓰는 중, 우리 앱 쓰는 중. A 묶음은 이 셋에 따라 달라서 칸을 나눴어요.

## 2. 화면 띄우기 묶음 (꺼짐 조합 8가지)

지금 코드: 울림 서비스는 권한과 상관없이 떠서 소리는 늘 나요. 화면은 '다른 앱 위에 표시'가 있으면 앱이 직접 띄우고, 없으면 전체 화면 알림에 맡겨요. 알림이 꺼져 있으면 울림 알림, 기다림 알림이 모두 안 떠요.

| 줄 | 꺼진 것 | 잠김 (지금) | 다른 앱 쓰는 중 (지금) | 경고 (지금) | 정할 반응 |
|---|---|---|---|---|---|
| C-01 | 없음 | 울림 화면 뜸 | 울림 화면 뜸 | 없음 | 그대로 |
| C-02 | N | 울림 화면 뜸(O로). 울림 알림, W2와 W3 기다림 알림 없음 | 울림 화면 뜸 | H2-2 '알림이 꺼져 있어요' | 그대로. W2 '깼어요' 뒤 화면 글과 홈 띠가 안내를 맡아요(결정 145). 실기 확인: 잠김에서 O만으로 화면이 뜨는지 |
| C-03 | O | 전체 화면 알림으로 울림 화면 뜸 | **위에서 내려오는 알림만 떠요.** 누르면 화면이 열림. 홈 버튼을 누르면 화면이 다시 안 떠요 | H2-3 | 그대로. W3 2분마다 화면 켜기는 알림 소리로만 알려요 |
| C-04 | F | 울림 화면 뜸(O로) | 울림 화면 뜸 | H2-4 | 그대로 |
| C-05 | N + O | **화면도 알림도 없음. 소리만 나요** | 같음 | H2-1 '알람이 울려도 화면이 안 떠요' | 아래 R1 |
| C-06 | N + F | 울림 화면 뜸(O로) | 울림 화면 뜸 | H2-2 | C-02와 같음 |
| C-07 | O + F | 잠금 화면에 알림만(소리 나고, 누르고 잠금을 풀면 화면이 열림) | 위에서 내려오는 알림만 | H2-3 | 그대로. 실기 확인: 잠금 화면 알림을 눌러 바로 열리는지 |
| C-08 | N + O + F | 소리만 | 소리만 | H2-1 | 아래 R1 |

**R1. 소리만 나고 끌 길이 없을 때 (C-05, C-08)**
- 정할 반응(추천): 앱 아이콘을 눌러 열면 홈이 아니라 바로 울림 화면(D0)이 열리게 해요. 지금 동작은 실기 확인이 필요해요.
- 알람 저장 때 막기: 이 조합에서 알람을 저장하면 시트 '이대로는 알람이 울려도 끌 화면이 안 떠요'와 버튼 '권한 켜기', '그래도 저장'. 지금은 저장 때 검사가 없어요.
- 1분 울림 뒤 쉬는 시간과 다시 울림은 지금 규칙 그대로(아무도 안 끄면 1분 울리고 쉼, 결정 F).

## 3. 제때 소리 내기 묶음

### 3-1. 권한과 설정

| 줄 | 상황 | 알람 울림 (지금) | 경고, 푸시 (지금) | 정할 반응 | 다시 켰을 때 |
|---|---|---|---|---|---|
| C-11 | 정확한 알람 꺼짐 (안드로이드 12만 끌 수 있음, 13 이상은 `USE_EXACT_ALARM`이라 늘 켜짐) | 덜 정확한 예약으로 바꿔 울려요. 몇 분 늦을 수 있어요. 서비스 시작이 막히면 폰 기본 알람음 알림으로 대신 | 배너, 권한 줄 없음. 진단 기록만 | 안드로이드 12에서만 T2 필수 카드에 '정확한 알람' 줄과 배너 하나를 더해요(문구: '알람이 몇 분 늦게 울릴 수 있어요') | 신호를 받아 전체 다시 예약, 울리던 것은 이어가요(지금 있음) |

| C-13 | 배터리 '제한'(`isBackgroundRestricted`) | 서비스가 못 떠서 소리, 화면이 막힐 수 있어요 | **검사 없음** | 결정 143대로 검사를 더해요. 배너는 H2-5와 같은 자리, 문구 '배터리 사용이 '제한'으로 되어 있어요 / 알람이 울리지 않을 수 있어요'. 다른 필수 권한보다 먼저 보여요(5절) | 앱을 열 때 다시 읽음 |

### 3-2. 방해 금지와 삼성 루틴 (TSK-177 댓글 사례)

지금 코드: 방해 금지 상태를 읽는 곳이 없어요. 울림 채널에 '방해 금지 무시'만 걸려 있어서, 알림 소리에는 듣지만 앱이 직접 트는 알람 소리는 방해 금지 '알람 허용'이 꺼져 있으면 막혀요.

| 줄 | 방해 금지 | 알람 허용 | 허용 앱에 우리 앱 | 알람 소리 (예상) | 울림 화면 | 정할 반응 |
|---|---|---|---|---|---|---|
| D-01 | 꺼짐 | 상관없음 | 상관없음 | 남 | 뜸 | 없음 |
| D-02 | 켜짐(루틴 시간 안) | 켬(기본값) | 상관없음 | 남 | 뜸 | 없음 |
| D-03 | 켜짐(루틴 시간 안) | 끔 | 있음 | 실기 확인(허용 앱은 알림에 듣는데, 앱이 트는 알람 소리에도 듣는지 모름) | 뜸 | 실기 결과에 따라 D-04와 같게 하거나 없음 |
| D-04 | 켜짐(루틴 시간 안) | 끔 | 없음 | **안 남**(진동도 막힐 수 있음, 실기 확인) | 뜸(화면 띄우기는 방해 금지와 상관없음) | 아래 R2, R3 |
| D-05 | 루틴 시간 밖(지금은 꺼짐, 알람 시각에 켜짐) | 끔 | 없음 | 알람 시각에 루틴이 켜져 있으면 D-04와 같음 | 뜸 | 앱은 루틴 일정을 읽을 수 없어요. 그래서 R2의 '울리기 10분 전 점검'이 필요해요 |
| D-06 | 켜짐 | 상관없음 | 상관없음 | 방해 금지 접근 권한이 없으면 우리 앱은 방해 금지를 바꿀 수 없음 | | R3 |

**R2. 앱이 막힘을 알아채는 때 (추천)**

| 때 | 하는 일 | 보여 주는 것 |
|---|---|---|
| 알람 저장 | 지금 방해 금지가 켜져 있고 알람 허용이 꺼져 있으면 | 저장은 되고 시트 '지금 방해 금지가 알람 소리를 막고 있어요' + 버튼 '설정 열기', '괜찮아요' |
| 앱을 열 때 | 같은 검사 | 홈 배너 H2-6(새) '방해 금지가 알람 소리를 막고 있어요 / '알람' 허용을 켜 주세요' |
| 전날 밤 9시 | 지금 있는 배터리 점검을 '내일 알람 점검'으로 넓혀 함께 봐요. 이때 루틴이 아직 안 켜졌으면 못 알아채요 | 푸시 하나에 문제를 모아요. 예 '내일 알람이 소리 없이 울릴 수 있어요 / 방해 금지가 알람을 막고 있어요' |
| 울리기 10분 전 | 알람 시각 10분 전에 한 번 깨어 방해 금지를 봐요(루틴 시간대를 잡으려고) | 막혀 있으면 R3 |
| 울린 뒤 | 울릴 때 막혀 있었으면 기록 | 다음에 앱을 열 때 한 번 '오늘 알람이 방해 금지 때문에 소리 없이 울렸어요' + '설정 열기' |

**R3. 울리기 직전 막혀 있을 때 (사용자에게 물을 것)**
- 추천: **사용자가 미리 켠 경우에만** 울리는 동안 방해 금지를 '알람만 허용'으로 잠깐 바꾸고, 끈 뒤 원래대로 돌려요. 방해 금지 접근 권한(T2 기타 카드)이 있어야 해요. 처음 값은 꺼짐이에요. 사용자 설정을 앱이 바꾸는 일이라 묻지 않고 하지 않아요.
- 켜지 않았으면: 화면은 띄우고 기록만 남겨요(R2 '울린 뒤').
- **한계 (ISS-057, 11-26 개발 확인)**: 안드로이드 15(API 35)부터는 앱이 방해 금지를 바꾸면 '앱 규칙' 하나만 켜고 꺼요. 사용자가 직접 켠 방해 금지나 삼성 루틴이 더 엄격하면 그쪽이 이겨서, 앱이 알람 소리를 풀 수 없어요. 그래서 안드로이드 15, 16에서는:
  - 울릴 때 방해 금지를 바꾸지 않고 흐름 로그에 `dnd_cannot_override`만 남겨요.
  - 설정 탭 '방해 금지 모드 예외' 토글은 켜지지 않고 T2-1 '알람 허용' 안내로 보내요.
  - 예전 판이 남긴 앱 규칙이 있으면 앱 시작 때 한 번 꺼요(사용자가 켠 방해 금지는 그대로).
- 안드로이드 14까지: 바꾼 상태를 저장해 두고, 울리는 중 앱이 강제 종료돼 되돌리지 못했으면 다음 앱 시작(또는 폰 재시작) 때 원래 값으로 돌려요(`dnd_leftover_restored`).

**허용 앱 추가 안내 화면 (새, 추천)**
- 이름: T2-1 '방해 금지 중에도 울리게'. T2 기타 카드 '방해 금지 모드 예외' 줄과 R2 시트, 배너에서 열려요.
- 내용: 세 단계 그림 안내. 1 '방해 금지' 설정에서 '알람'을 켜기(가장 확실), 2 삼성 '모드와 루틴'의 수면 모드나 루틴을 쓰면 그 모드의 '알람' 허용 켜기, 3 '앱 예외(허용 앱)'에 morning-up 넣기.
- 버튼: '방해 금지 설정 열기'(안드로이드 방해 금지 설정으로 바로 감, 삼성은 루틴 화면을 바로 못 열 수 있어 글로 안내), '닫기'.
- 우리 앱이 허용 앱 목록에 들었는지는 공개된 방법으로 읽을 수 없어요(개발 확인). 그래서 상태 표시 없이 안내만 해요.
- TSK-094 방해 금지 검사는 이 절의 R2, R3과 같은 때, 같은 문구로 만들어요.

### 3-3. 배터리 킬 4경우

| 줄 | 경우 | 예약 | 알람 울림 | 앱이 할 수 있는 안내 (정할 반응) |
|---|---|---|---|---|
| B-01 | 시스템 절전이 앱을 정리(메모리 정리, 디바이스 케어 새벽 정리) | 남음 | 울림(시각이 되면 안드로이드가 앱을 다시 깨움) | 없음. QA에서 울리는지만 확인 |
| B-02 | 삼성 '잠자는 앱' / '깊은 잠자는 앱' | 남음 | 잠자는 앱은 늦을 수 있고, 깊은 잠자는 앱은 안 울릴 수 있음(실기 확인) | 배터리 예외를 받으면 자동 재우기 목록에서 빠져요(지금 있음). 사용자가 직접 깊은 잠에 넣으면 '제한'으로 보이는지 실기 확인 뒤 C-13 배너로 알려요. 밤 9시 푸시도 못 뜰 수 있어서 **앱을 열 때와 알람 저장 때** 검사가 중심. T2 기타 카드의 '삼성 절전 예외' 화살표 그대로 |
| B-03 | 사용자 강제 종료(설정의 '강제 종료', 정리 앱, 일부 루틴의 '앱 닫기') | **모두 지워짐** | 앱을 다시 열 때까지 안 울림. 앱도 서버 푸시도 못 보내요(우리 앱은 서버가 없음) | 앱을 다시 열면 다시 예약(지금 있음). 강제 종료 흔적을 알아채면 한 번 알려요: '앱이 강제로 닫혀 알람이 꺼져 있었어요. 지금 다시 맞췄어요'. 그동안 지나간 알람은 '놓친 알람'으로 보여 주되, 문구를 '폰이 꺼져 있는 동안'이 아니라 '앱이 닫혀 있는 동안'으로 나눠요(지금은 둘 다 '폰이 꺼져 있는 동안'). 도움말 한 줄 '강제 종료하면 다시 열 때까지 알람이 울리지 않아요' |
| B-04 | 배터리 0으로 폰 꺼짐 | 꺼진 동안 못 울림 | 안 울림. 켜지면 다시 예약하고, 지난 지 10분 안이면 바로 울림, 넘으면 '놓친 알람' 알림(지금 있음) | 밤 9시 점검에 배터리 확인을 더해요: 내일 아침 알람이 있고 배터리 20% 아래이고 충전 중이 아니면 '배터리가 n% 남았어요. 충전하지 않으면 알람이 울리지 않을 수 있어요' |

## 5. 여러 개 꺼졌을 때 경고 순서

지금 코드: 배너는 한 번에 하나, 순서는 N+O → N → O → F → 배터리. 배터리는 필수 셋이 다 켜졌을 때만. 하단 메뉴에 '확인 필요' 말풍선, 배너를 누르면 권한 시트(PL2)가 필수부터 열려요.

| 순서 (추천) | 배너 | 이유 |
|---|---|---|
| 1 | 배터리 '제한'(C-13, 새) | 서비스가 아예 못 떠서 소리도 화면도 막혀요 |
| 2 | 방해 금지가 알람 막음(H2-6, 새) | 소리가 0이에요 |
| 3 | N + O (H2-1) | 화면도 알림도 없음 |
| 4 | O (H2-3) | 다른 앱 쓰는 중에 화면이 안 떠요 |
| 5 | N (H2-2) | |
| 6 | F (H2-4) | O가 있으면 영향이 작아요 |
| 7 | 정확한 알람(안드로이드 12만) | 몇 분 늦음 |
| 8 | 배터리 예외 없음(H2-5) | 대개 제시각에 울려요 |

- 추천: 2개 이상 꺼지면 배너 제목은 가장 위의 것으로 두고, 설명 끝에 '그 밖에 n개 더'를 붙여요. 누르면 PL2(권한 시트)가 꺼진 것만 모아 보여 줘요.
- 지금 순서에서 O를 N보다 앞에 두는 이유: N만 꺼지면 화면은 떠요(C-02), O만 꺼지면 다른 앱 위에서 안 떠요(C-03).

## 6. 중간에 끔

안드로이드 규칙(실기 확인): 알림, 위치처럼 '실행 중에 묻는 권한'을 설정에서 끄면 안드로이드가 앱을 닫아요. 정확한 알람 권한을 끄면 앱을 닫고 정확한 예약을 모두 지워요. 다른 앱 위에 표시, 전체 화면 알림, 배터리 예외, 접근성, 방해 금지는 앱을 닫지 않아요.
지금 코드: 울리는 중에 권한 변화를 지켜보는 곳이 없어요. 다음 화면 띄우기나 알림 갱신부터 조용히 실패하고 소리는 계속 나요(앱이 닫히지 않는 경우).

| 줄 | 끈 때 | 끈 것 | 지금 / 예상 | 정할 반응 |
|---|---|---|---|---|
| M-01 | 대기(다음 알람 기다림) | N, L | 앱이 닫혀도 예약은 남아요. 제시각에 울림(화면은 2절 조합대로) | 다음에 앱을 열 때 배너 |
