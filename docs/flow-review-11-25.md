## 1. 높음

### 1-1. 새 알람은 못 들으면 2분 뒤 그대로 끝남
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 알람 만들기(S0, S3 다시 울림 시트) → 울림(D0) |
| 증상 | 새 알람 처음 값은 '다시 울림' 꺼짐(횟수 0)이에요. 이 알람이 울릴 때 아무도 안 끄면 2분 울린 뒤 바로 '놓친 알람'으로 끝나요. 우리는 스누즈가 없어서, 잠결에 2분을 못 들으면 그날 알람은 더 오지 않아요. 깨우는 앱의 가장 기본 약속(끌 때까지 깨움)이 처음 값에서 깨져 있어요 |

| 다른 안 | 처음 값 '무제한'(알라미와 같음). 폰을 두고 나간 날 하루 종일 울리는 문제(F4가 막으려던 것)가 다시 생겨서 추천하지 않아요 |
| 우선순위 | 높음 |

### 1-2. 다시 잠들기 방지가 꺼진 알람뿐이면 '한 번 더 확인', '여러 번 묻기'가 아무 일도 안 함
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 알람 편집(S0) ↔ 설정(T1 '깼는지 묻기', '한 번 더 확인', T1-1, T1-2) ↔ 실험실(T3 '여러 번 묻기', T3-2) |
| 증상 | ① 알람마다의 '다시 잠들기 방지'는 새 알람에서 처음 꺼짐이에요. 그런데 T1 '한 번 더 확인'은 처음 켜짐, 실험실 '여러 번 묻기'는 켜면 '깼는지 3번 물어요'로 보여요. 켜 둔 알람이 하나도 없으면 어느 쪽도 실제로는 묻지 않는데, 화면은 켜진 것처럼만 보여요(Leader가 찾은 결정 146 예시). ② 같은 기능이 편집에서는 '다시 잠들기 방지', 설정에서는 '깼는지 묻기'라서 둘이 이어져 있다는 걸 알기 어려워요. 지금 안내는 고정된 작은 글('알람마다 켜고 끄기는 알람 편집에서 해요') 하나뿐이에요 |
| 근거 | 결정 145 5절(알람마다 토글만 남김), 결정 146 1절(알람 하나만 빼기는 이 토글을 따름), 3절 표 '알람마다'. 코드 `core/model/.../Alarm.kt:30` `WakeCheck(enabled = false)`, `EditViewModel.kt:390` 새 알람 주석 '다시 잠들기 방지 꺼짐', `RingStateMachine.kt` `finish()`는 `wakeCheckEnabled`가 거짓이면 W1에서 끝(여러 번 묻기 값 `askTotal`은 보지 않음). 문구 `feature/settings/src/main/res/values/strings.xml:157, 166, 189, 193`, `feature/edit/src/main/res/values/strings.xml:27` |
| 알라미 | '다시 잠들기 방지'는 편집 화면 한 곳에만 있고 이름도 하나예요(1-4, 캡처 26~28, 113). 설정 탭에는 없어요 |
| 추천 | **우리식 개선** 두 가지. ① 켜진 알람 가운데 '다시 잠들기 방지'를 켠 알람이 하나도 없으면 T1 카드 아래와 T3 '여러 번 묻기' 줄 둘째 줄에 '켜 둔 알람이 없어요. 알람 편집에서 '다시 잠들기 방지'를 켜야 물어요'를 보여요(글은 가안). ② T1 카드의 '깼는지 묻기' 이름을 '다시 잠들기 방지'로 맞춰요(줄은 '묻는 때', '한 번 더 확인'처럼 값 이름으로) |
| 하지 않은 안 | 새 알람의 '다시 잠들기 방지' 처음 값을 켬으로 바꾸기. 낮잠 알람까지 W2가 뜨게 되고, 1-1 처음 값 변경과 겹쳐 한꺼번에 바꾸는 폭이 커서 이번엔 추천하지 않아요. 사용자가 원하면 같이 정해요 |
| 우선순위 | 높음 |

### 1-3. 울리는 중, 쉬는 중에 그 알람을 끄거나 지우거나 편집해도 울림이 계속됨
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 울림(D0) → 1분(지금은 2분) 울림 끝 → 쉬는 중(다시 울림 간격) → 홈(H0)에서 토글 끄기, 선택 모드 삭제(H7), '모든 알람 끄기', 편집(S0) 저장 |
| 증상 | 쉬는 중에는 울림 화면이 닫혀서(결정 70) 앱 홈으로 갈 수 있어요. 여기서 그 알람 토글을 끄면 카드는 꺼진 모양이 되고 '이번만 쉬기' 제안까지 뜨지만, 몇 분 뒤 그대로 다시 울려요. 지운 알람도, 시각을 바꿔 저장한 알람도 옛 값대로 다시 울려요. '남은 확인을 멈췄어요' 같은 안내도 없어요. 사용자는 '껐는데 울린다'로 보게 돼요 |
| 왜 이렇게 되나 | 홈과 편집이 부르는 `cancelFor`가 W2, W3 단계(`isCheck`)에서만 멈춰요. 울리는 중, 쉬는 중, 미션 중이면 아무것도 안 하고 false를 돌려요. ADR 상태표에도 '쉬는 중 + 그 알람 끔, 지움, 편집 저장' 줄이 없어요(36행은 W2, W3만) |
| 근거 | `core/alarm/.../ring/RingWakeCheckGate.kt:34-39`, `RingController.kt:161`(쉬는 중 화면 None), `feature/home/.../HomeViewModel.kt` `setEnabled`, `turnOff`, `deleteSelected`, `EditViewModel.kt` `save()`. `docs/adr/0002-alarm-engine.md` 21~24, 36, 39행. 결정 70, 145 7절, 153, 154 |
| 알라미 | 미루기 중에는 홈(알람 목록)에 아예 못 가요. 뒤로, 홈 키, 아이콘, 새로 띄우기 모두 미루기 화면으로 돌아와요. 끄는 길은 '알람 끄기(미션)' 하나예요(5-1, 캡처 116~118) |
| 추천 | **수용(우리식)**. 화면 전체를 막지는 않고 그 알람만 막아요. ① 그 알람이 울리는 중, 쉬는 중, 미션 중이면 카드 토글, 선택 모드의 끄기, 이번만 쉬기, 삭제, 편집 저장을 막고 토스트 '지금 울리는 알람이에요. 울림 화면에서 꺼 주세요'(가안). ② 쉬는 중에는 홈 위에 띠 '오전 6:40에 다시 울려요'(가안, 누르면 울림 화면. 쉬는 중 알림 결정 70과 같은 곳으로)를 둬요. 자리는 '한 번 더 확인이 남았어요' 띠(결정 145)와 같아요 |
| 하지 않은 안 | 끄면 울림까지 같이 끝내기. 쉬는 중에 앱을 열어 토글만 끄면 미션 없이 끝나는 꼼수가 돼요. 지금 코드가 울림을 이어 가는 것 자체는 맞고, 화면이 그걸 숨기는 게 문제예요 |
| 우선순위 | 높음 |
| 사용자 결정 | 필요(막는 범위, 문구). ADR 상태표에 줄을 더하는 건 개발 몫 |

## 2. 중간

### 2-1. 여러 번 묻기가 1시간 상한에 걸려 끝나도 '조금 뒤 한 번 더 물어볼게요'가 뜸
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 실험실 '여러 번 묻기' 켬 → W2 → W3 여러 번 |
| 증상 | 다음 W3를 물을 때가 그 바퀴 미션 끝에서 60분을 넘으면 엔진은 조용히 끝내요. 그런데 방금 끝낸 W3의 끝 화면은 '마지막'인지를 정한 횟수로만 판단해서 '조금 뒤 한 번 더 물어볼게요'를 보여 주고, 그 뒤엔 아무것도 오지 않아요. 홈 띠와 알림도 말없이 사라져요 |
| 얼마나 자주 | 평균값만으로도 걸려요. 예: 다시 물어보기 10분, 5번, 간격 평균 10분, 각 W3에 3분 걸려 답하면 10 + (10 + 3) × 4 = 62분이라 다섯째를 못 물어요. 사용자는 '5번'을 골랐는데 4번만 묻는 셈이에요 |
| 근거 | 결정 146 3절(60분 상한). `RingStateMachine.kt` `multiPassed`(상한이면 `EndedByTimeCap`으로 끝), `feature/ring/.../RingRoute.kt:114`(끝 화면은 `isLast`만 봄), 문구 `feature/ring/src/main/res/values/strings.xml` `ring_multi_next` |
| 알라미 | 해당 없음(다시 잠들기 방지가 유료라 비교 못 함, 5-1) |
| 추천 | **우리식 개선**. 상한으로 끝나는 W3 끝 화면은 '오늘 확인을 다 마쳤어요'(이미 있는 글)로 보여요. 상한을 늘릴지는 손대지 않아요(결정 146 이유 그대로) |
| 우선순위 | 중간 |
| 사용자 결정 | 필요 없음(이미 있는 글을 맞는 때에 쓰는 버그 고침). Leader 판단으로 개발에 넘기면 돼요 |

### 2-2. 다른 알람이 쉬는 중에 시각이 된 알람은 조용히 건너뜀
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 알람 두 개(예: 6:30, 6:35 '진짜 마지막') → 6:30이 쉬는 중에 6:35 시각 |
| 증상 | 울리는 중, 쉬는 중, 미션 중이면 뒤 알람은 '지나감' 진단 기록만 남고 울리지 않아요. 사람이 자는 쉬는 중에도 그래요. 앞 알람이 다시 울림 횟수를 다 써서 '놓침'으로 끝나면, 백업으로 맞춘 뒤 알람은 한 번도 안 울린 채 끝나요. 화면과 알림 어디에도 건너뛴 걸 알리지 않아요 |
| 근거 | ADR 0002 39행, `RingStateMachine.kt` `alarmFired`(W2, W3 단계만 새 알람이 이김, 결정 145 7절), `AndroidRingEffectRunner.kt:106`(`MarkPassed`는 기록만) |
| 알라미 | 이번 조사에서 보지 못했어요(1-17). 미루기 중에는 홈이 막혀 있어 알람을 겹쳐 시험하지 않았어요 |
| 추천 | **우리식 개선**. 앞 알람이 **쉬는 중**일 때 뒤 알람 시각이 오면 뒤 알람이 울려요(W2, W3 대기와 같은 '새 알람이 이김'). 앞 알람의 남은 울림은 끝내요. 울리는 중, 미션 중은 사람이 깨어 있으니 지금처럼 둬요 |
| 우선순위 | 중간 |
| 사용자 결정 | 필요(울림 규칙 바뀜) |

### 2-3. 알림 권한이 꺼지면 미션 비상구가 없어지는데 그 위험이 잘 안 보임
| 칸 | 내용 |
|---|---|
| 흐름 단계 | 권한(O2-1, H2 배너) → 미션(M1~M4) → 미션 비상구(알림 따라 쓰기) |
