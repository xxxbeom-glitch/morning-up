# ADR 0002: 알람 엔진 구조와 울림 상태표

- 날짜: 2026-11-17 (자동 실행 중 결정, 아침에 사용자 확인 필요)
- 상태: 채택

## 배경
알람 앱에서 가장 중요한 것은 '정시에 반드시 울리고, 아무도 안 끄면 정한 대로 멈추는 것'이에요. 이 판단이 안드로이드 코드에 흩어지면 테스트하기 어려워요.

## 결정

### 1. 판단은 순수 함수로
- `:core:model`의 `engine` 패키지에 `NextRingCalculator`, `KoreanHolidays`, `RingStateMachine`, `BootCatchUpPolicy`, `AlarmRescheduler`를 둬요. 안드로이드 없이 JVM 테스트로 돌아요.
- 시각은 `java.time`으로 다뤄요(minSdk 26이라 그대로 써요).
- 상태표는 `reduce(state, event, now)`가 새 상태와 '효과' 목록을 돌려줘요. 서비스는 효과만 실행해요(소리, 진동, 화면, 타이머 예약).

### 2. 울림 상태표

| 지금 상태 | 사건 | 다음 상태 | 효과 |
|---|---|---|---|
| 없음, 끝남 | 알람 시각 | 울리는 중 | 소리 100%, D0 띄우기, 60초 뒤 '울림 끝' 예약, 이 알람 다음 시각 다시 예약 |
| 울리는 중 | 울림 끝(60초) | 남은 횟수 있으면 쉬는 중(횟수 1 깎음), 없으면 놓침 | 소리 멈춤, 쉬는 간격 뒤 '쉼 끝' 예약 / 놓친 알람 알림 |
| 쉬는 중 | 쉼 끝 | 울리는 중 | 소리 100%, D0, 60초 예약 |
| 울리는 중, 쉬는 중 | 미션 시작 | 미션 중(끝낸 미션 다음부터) | 소리 20%, 미션 화면, 59초 예약 |
| 울리는 중, 쉬는 중 | 미션 없이 끄기 | 미션을 다 끝낸 것과 같음 | |
| 미션 중 | 미션 조작 | 미션 중 | 59초 다시 채움 |
| 미션 중 | 59초 끝 | 울리는 중 | 소리 100%. **횟수 안 깎음**, 끝낸 미션은 유지 |
| 미션 중 | 미션 하나 끝 | 남았으면 다음 미션 / 다 끝났으면 W2 기다림(켜짐) 또는 꺼짐 | 다음 미션 59초 / 소리 멈춤, W1, 묻는 시각 예약 |
| W2 기다림 | 묻는 시각 | W2 묻는 중 | W2 화면, 답할 시간 예약 |
| W2 묻는 중 | '깼어요' | 꺼짐 | 타이머 취소 |
| W2 묻는 중 | 답할 시간 끝 | 울리는 중 | 소리 100%. **미션 처음부터, 횟수는 처음 값으로** |
| 울림 진행 중 아무 상태 | 다른 알람 시각 | 그대로 | 뒤 알람은 '지나감' 기록, 다음 시각 다시 예약(한 번 알람이면 끔) |
| 꺼짐, 놓침 | (끝) | | 한 번 알람이면 토글 끔, 진단 기록 |

- 횟수: '다시 울림 3번'은 처음 울림 뒤 3번 더 울린다는 뜻으로 정했어요. 1분 울림이 끝날 때만 깎아요(dev-plan 2-0 추천안).
- W2 시간 초과 뒤 횟수를 처음 값으로 되돌리는 것은 dev-plan에 없어서 정한 것이에요. '한 번 깬 사람은 끝까지 깨운다'는 추천안의 뜻을 따랐어요.
- 쉬는 중에도 알림을 눌러 미션을 시작할 수 있어요.

### 3. 저장 위치
- 알람 목록(Room `morningup.db`), 울리는 중 상태(DataStore `ring_session`), 진단 기록(Room, 최대 500줄)은 모두 기기 보호 저장소에 둬요. 잠금을 풀기 전(재부팅 직후)에도 읽혀야 해서예요.
- 알람에 `nextTriggerAt`(다음 예약 시각)을 저장해요. 폰이 꺼져 있다 켜졌을 때 놓친 알람을 알아내는 데 써요.

### 4. 예약 방식
- 알람 시각과 '쉼 끝'은 `setAlarmClock`(상태 표시줄 시계 아이콘, 잠자기 모드에서도 정시). 정확한 알람 권한이 없어 `SecurityException`이 나면 `setAndAllowWhileIdle`로 대신하고 진단 기록에 남겨요.
- 60초 울림 끝, 59초, W2 시각은 `setExactAndAllowWhileIdle`로 예약해요. 앱이 죽어도 이어지게 서비스 안 타이머가 아니라 AlarmManager에 맡겨요.
- 다시 예약 신호: 잠금 전 부팅, 부팅, 시간 변경, 시간대 변경, 앱 업데이트, 정확한 알람 권한 변경. 모두 같은 `rescheduleAll` 하나로 처리해요.
- 폰이 꺼져 있는 동안 지난 알람: 켜진 뒤 10분 안이면 바로 울리고, 넘으면 '놓친 알람' 알림만 남겨요(dev-plan 추천안).

### 5. 울림 서비스
- 포그라운드 서비스 종류 `systemExempted`(알람 앱 허용 종류). API 34 미만은 종류 없이 시작해요.
- 소리는 알림 채널 소리가 아니라 `MediaPlayer`(`USAGE_ALARM`)로 앱 안 기본음 `res/raw`를 직접 울려요. 채널 소리를 꺼 둬도, 고른 소리 파일을 못 읽어도 반드시 울리게 하려는 것이에요(검수 초점 6). 알림 채널은 소리 없이 둬요.
- 공휴일 목록: 2026~2027. 2026년 노동절(5/1)과 제헌절(7/17)은 2026년 법 개정으로 공휴일이 됐어요. 2027년에 토요일과 겹치는 노동절, 제헌절의 대체공휴일 여부는 확실하지 않아 넣지 않았어요(넣지 않으면 그날 울려서 안전한 쪽이에요).

### 6. 안드로이드 연결(core:alarm)
- 모든 울림 신호(알람 시각, 울림 타이머, 화면 버튼)는 `RingService` 하나를 지나요. 서비스는 받자마자 앞으로 뜨고, `RingController`가 저장된 상태를 읽어 상태표에 넣고 저장한 뒤 효과를 실행해요. 동시에 온 신호는 Mutex로 하나씩 처리해요.
- 쉬는 중과 W2 기다림에는 서비스를 멈추고 알림만 남겨요. 다시 울릴 때(쉬는 시간 끝, W2 묻기)는 알람 시계 예약(`setAlarmClock`)으로 깨워요. 1분 울림, 59초 미션, W2 답할 시간은 서비스가 떠 있는 동안이라 `setExactAndAllowWhileIdle`을 써요.
- 정확한 알람 권한이 없거나 막히면 `setAndAllowWhileIdle`로 대신 예약하고 진단 기록에 `fallback_schedule`을 남겨요. 몇 분 늦을 수 있어요.
- 서비스 시작이 막히면(`ForegroundServiceStartNotAllowedException`) 진단 기록에 `service_start_failed`를 남겨요. 알람 시계 앱 권한(USE_EXACT_ALARM)이 있으면 안드로이드 12 이상의 백그라운드 시작 제한에서 빠지는 것으로 알고 있지만 폰에서 확인해야 해요.
- 시스템 신호(부팅, 시간, 시간대, 앱 업데이트, 권한 변경)를 받으면 전부 다시 예약하고, 저장된 울림이 있을 때만 서비스를 다시 띄워요. 앱을 열 때도 전부 다시 예약해요.
- 울림 화면은 2단계에서는 상태만 그리는 임시 `RingActivity`예요. 잠금 화면 위에 뜨고 뒤로 가기는 W1에서만 돼요.

## 결과
- 상태표와 계산은 모두 JVM 테스트로 막혀요. 폰에서만 확인할 수 있는 것(잠자기 모드, 잠금 전 부팅, 플립 바깥 화면)은 아침 확인 목록에 있어요.
