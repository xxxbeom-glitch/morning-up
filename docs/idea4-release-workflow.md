# 아이디어 4: 출시까지 전체 흐름 (정리안, 확정 아님, 11-23 계정 사실 반영)

11-23 [기획 2] 작성. 원문은 `docs/ideas-11-22.md` 4번: "이걸 실제 출시로 고려할 때 단위별로 끊어서 전체 워크플로우에 대해서 한번 정리."
조건: 혼자 하고, 테스트폰을 살 돈이 없고, 무료로 가볍게 푸는 것이 목표예요.

## 결론

- 지금부터 구글 플레이 출시까지 **9단계, 대략 5~7주**예요. 앱 기능은 0~10단계 개발을 한 바퀴 다 돌았어요. 그래서 남은 일은 대부분 '고치고, 시험하고, 등록하는 일'이에요.
- 플레이 개발자 계정은 **이미 있어요**. 이름은 '루미안'이고 개인 계정이에요. 같은 계정으로 '온톡'을 비공개 테스트를 거쳐 프로덕션에 출시했어요(1.0.48, 2026-10-05). 그래서 계정 만들기, 등록비, 신원 확인은 필요 없어요.
- 개인 계정이라 새 앱마다 **테스터 12명이 14일 동안 계속 참여하는 비공개 테스트**가 필요해요. 온톡 때처럼 **외부 테스터 업체**로 해결해요.
- 급한 일이 하나 있어요. 계정에 **'2027년 2월까지 판매자 상태 선언'** 알림이 떠 있어요. 하지 않으면 앱이 삭제될 수 있다는 경고라서 사용자가 직접 처리해야 해요.

## 단계별 자세한 내용

### 지금 바로: 판매자 상태 선언 (사용자 직접)
- 플레이 콘솔에 '2027년 2월까지 판매자 상태 선언' 조치 알림이 떠 있어요. 하지 않으면 계정의 앱이 삭제될 수 있다는 경고예요. 온톡도 같은 계정이라 영향을 받아요.
- 선언에 넣을 정보는 **어떤 항목을 넣을지 사용자 확인이 필요**해요(CLAUDE.md 규칙). Claude가 대신 입력하지 않아요.
- 계정 정보: 이름 '루미안', 개인 계정, 이미 온톡을 출시한 계정이에요. 새 계정을 만들 일은 없어요.

### 1. MVP 범위 잠그기 (기획, 사용자)
- 이미 정한 것: 다시 잠들기 확인 횟수(결정 136, 137, 139), 카메라 미션 보류(138), 수면 라운지 빼기(140, 141).
- 정할 것
  - (정해짐, 결정 142) 날씨(위치 권한)와 전원 종료 방지는 첫 버전에 넣어요. 그래서 5단계에서 위치, 접근성 권한 신고와 위치정보사업 신고 확인을 해요.
  - 앱 이름: 아직 미정이에요('깨'/GGAE 후보). **5단계(스토어 글과 그림) 전에 확정**해야 해요. 그 전에 플레이 스토어에서 같은 이름이 있는지, 상표가 있는지 확인해요.
  - 앱 아이콘: 'App Icon / Clock Day Black'으로 확정됐어요. 원래 앱에는 반영했어요(b423b06).
- 끝 기준: 결정 문서에 MVP 기능 목록 한 표.

### 2. 남은 디자인과 개발 (디자인, 개발)
- 개발: 확인 횟수(결정 136, 137, 139), 수면 라운지 숨김과 하단 메뉴 탭 2개(140, 141), 출시판에서 재생 서비스 권한 빼기, 작업 폴더의 미커밋 `MorningUpApp.kt` 정리, 앱 이름 반영, 실제 알람음 넣기, 시작 성능 프로필(울림 화면이 빨리 뜨게).
- 디자인: S4 시트 줄, Bottom Nav 탭 2개, 다크 화면 검수, 스플래시 확정.
- 콘텐츠: Pop Quiz, Drop Words 문제를 폰에서 직접 풀어 보며 검수해요(남은 일에 있음).
- 끝 기준: dev-plan '개발 후 필수 체크리스트' 통과. 사용자가 폰에서 확인하면 다음 단위로 넘어가요(단위마다 APK 확인 규칙).

### 3. 내 폰 2대로 사용성 테스트 (사용자, 개발)
- S24+와 Z플립5로 실제 아침 알람을 써 봐요. dev-plan 10단계대로 '2~3일 그냥 두기', '주말을 넘겨도 월요일 알람이 울리는지'를 확인해요.
- 밤 10시~아침 9시에는 폰 설치, 권한 변경, 알람 시험을 하지 않는 규칙을 그대로 지켜요.
- 끝 기준: 예비 알람(기본 시계) 없이 3일 연속 제때 울림.

### 4. 기기 호환성 조사 (아이디어 6 자리, 개발)
- 메모리 정리 앱, 방해 금지, 루틴, 제조사별 절전 때문에 알람이 실패할 수 있는지 조사하는 자리예요. 내용은 아이디어 6에서 정해요.
- 돈 없이 넓게 보는 방법은 7단계 비공개 테스트예요. 테스터 폰에서 울림 실패가 나면 알 수 있게, 앱 안 진단 기록을 보내는 방법을 이때 정해요.

### 5. 스토어 등록 준비물 (기획, 디자인, 마케팅)

| 준비물 | 내용 | 맡을 곳 |
|---|---|---|
| 앱 이름, 짧은 설명(80자), 긴 설명 | 손님이 보는 글이라 가운뎃점과 긴 줄표를 쓰지 않아요 | 기획, 마케팅 |
| 아이콘 512x512, 피처 그래픽 1024x500, 스크린샷 | Clock Day Black 아이콘, 라이트 화면 위주 | 디자인 |
| 개인정보처리방침 공개 주소 | 초안 `privacy-policy-draft.md`가 있어요. 무료로 올릴 곳(GitHub Pages, 노션 공개 페이지, 브랜드 사이트) 중 하나를 골라요 | 기획 |
| 데이터 보안 양식 | 수집하는 것(날씨용 대략적 위치), 저장과 전송 여부 | 기획, 개발 |

| 위치정보사업 신고 확인 | 날씨를 넣으니 신고가 필요한지 출시 전에 위치정보지원센터에 확인(`research/H-location-law.md`) | 기획, 사용자 |
| 콘텐츠 등급 설문, 대상 연령, 광고 없음 | 설문에 답해요 | 기획, 사용자 |
| 사업자 정보 | 루미안 정보 중 **어떤 항목을 넣을지 사용자 확인 필요** (CLAUDE.md 규칙) | 사용자 |

### 6. 출시판 빌드와 서명 (개발)
- 출시판 AAB를 만들고 플레이 앱 서명을 써요. 업로드 키는 저장소에 넣지 않고, 사용자가 따로 백업해 둬요(잃으면 업데이트가 어려워져요).
- 버전 번호 규칙, 코드 줄이기(R8), 대상 SDK 36 확인. 디버그 전용 '테스트' 페이지와 확인용 앱(온보딩, 미션)은 출시판에 안 들어가는지 확인해요.

### 7. 비공개 테스트 14일 (외부 테스터 업체)
- 개인 계정이라 새 앱도 테스터 12명 이상이 14일 동안 **계속** 참여해야 프로덕션을 신청할 수 있어요.
- 온톡 때처럼 외부 테스터 업체에 맡겨요(사용자: "깊게 생각 안 해도 될 거 같아").
- 이 기간에 업체 테스터 폰에서 알람이 제대로 울리는지 피드백도 받아 봐요. 4단계 호환성 조사와 이어져요. 업체가 피드백을 주지 않으면 알람이 울렸는지 앱 안 진단 기록으로 보는 방법을 2단계에서 정해요.

### 8. 프로덕션 신청과 출시
- 콘솔에서 프로덕션 접근을 신청하고 설문에 답해요. 심사는 보통 며칠, 길면 1주예요.
- 처음에는 단계적 출시(일부 사용자에게만 먼저)를 추천해요. 큰 문제가 나와도 피해가 작아요.

### 9. 출시 뒤 지표와 첫 업데이트
- 보는 지표: 설치 수, 삭제 수, 1일, 7일, 30일 유지율(플레이 콘솔 기본 통계), 비정상 종료와 응답 없음(Android vitals), 별점과 리뷰.
- 처음에는 플레이 콘솔 기본 통계만 써요. 따로 분석 도구를 넣으면 개인정보처리방침과 데이터 보안 양식이 늘어나서, 필요해지면 그때 정해요.
- 첫 업데이트 후보: 카메라, 바코드 미션(결정 138 보류), 수면 라운지 되살리기(140), 미션 아이디어 메모, 테스터와 리뷰에서 나온 고칠 것.
