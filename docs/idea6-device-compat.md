# 아이디어 6. 여러 기기에서 알람이 실패할 수 있는지 (기기 호환성 조사)

작성: [개발 13], 2026-11-23. 코드 기준 커밋 `b423b06`. 코드는 고치지 않고 읽기만 했어요.

## 결론 먼저

- **지금 설계로 흔한 경우는 대부분 막혀요.** 알람 예약은 안드로이드에서 가장 강한 방법(`setAlarmClock`)을 쓰고, 재부팅, 시간 변경, 앱 업데이트 뒤 다시 예약하는 장치도 이미 있어요. 잠금을 풀기 전(재부팅 직후)에도 울리게 만들어져 있어요.
- **앱이 막을 수 없는 구멍이 세 가지 있어요.**
  1. 사용자가 앱을 '강제 종료'하거나 정리 앱이 강제 종료하면 예약이 모두 지워져요. 앱을 다시 열 때까지 울리지 않아요.
  2. 방해 금지 모드나 삼성 '수면 모드'에서 '알람 허용'을 꺼 두면 소리가 안 나요.
  3. 삼성 '최대 절전 모드'에서는 허용한 몇 개 앱 말고는 아예 돌지 않아요.
- 앱이 할 수 있는 일은 **미리 알아채서 알려 주는 것**이에요. 첫 버전 전에 꼭 할 일은 아래 '우선순위' 1~5번이에요.
- 따로 큰 위험은 **구글 플레이 심사**예요. 접근성 서비스(전원 종료 방지)는 거절당할 가능성이 높아요. 정확한 알람과 전체 화면 알림도 심사 때 '알람 앱'이라고 신고해야 해요.

## 2. 실패할 수 있는 경우

표시: **막힘** = 지금 설계로 울려요 / **일부** = 조건에 따라 안 울릴 수 있어요 / **안 막힘** = 앱이 막을 수 없어요

### 2-1. 제조사 배터리 관리 (참고: dontkillmyapp.com)

| 경우 | 지금 | 이유 | 앱에서 할 수 있는 대책 |
|---|---|---|---|
| 삼성: 잠자는 앱, 깊은 잠자는 앱(안 쓰는 앱 자동으로 재우기) | 일부 | 배터리 '제한 없음'(최적화 제외)이면 자동으로 재우는 목록에서 빠져요. 사용자가 직접 '깊은 잠자는 앱'에 넣으면 막을 수 없어요 | 지금처럼 최적화 제외를 받고, 꺼지면 알려 주기(이미 있음). 도움말에 '절전 예외 앱'에 넣는 법 안내 |
| 삼성: 디바이스 케어 자동 최적화(새벽에 앱 정리) | 막힘 | 정리는 앱을 닫을 뿐, 강제 종료가 아니라 예약은 남아요 | 없음 |
| 삼성: 정해진 시간에 자동 재시작 | 막힘 | 재부팅 뒤 다시 예약하고, 잠금 전에도 울려요 | 없음 |
| 샤오미(MIUI, HyperOS): 자동 실행 꺼짐, 배터리 절약 | 일부 | 자동 실행이 꺼져 있으면 재부팅 뒤 신호를 못 받아 예약이 사라질 수 있어요 | 샤오미 기기만 '자동 실행' 설정으로 보내는 안내 줄 추가 |
| 오포, 비보, 원플러스, 리얼미 | 일부 | 샤오미와 비슷하게 자동 실행, 백그라운드 실행 허용이 따로 있어요 | 같은 안내 줄. 한국 점유율이 낮아 나중에 |
| 구글 픽셀(순정 안드로이드) | 막힘 | `setAlarmClock`은 순정에서 가장 잘 지켜져요 | 없음 |
| 화웨이 | 안 막힘 | 앱을 매우 공격적으로 죽여요 | 한국에서는 사실상 없음. 무시 |

### 2-2. 정리 앱, 강제 종료, 방해 금지, 루틴, 절전

| 경우 | 지금 | 이유 | 앱에서 할 수 있는 대책 |
|---|---|---|---|
| 사용자가 설정에서 '강제 종료' | 안 막힘 | 안드로이드가 그 앱의 예약을 전부 지우고, 다시 열 때까지 어떤 신호도 안 줘요 | 앱을 열면 다시 예약(이미 있음). 예약이 지워졌던 흔적을 알아채 '알람이 꺼졌던 적이 있어요' 알리기. 온보딩이나 도움말에 '강제 종료하면 알람이 안 울려요' 한 줄 |
| 정리 앱, 배터리 절약 앱(강제 종료 방식) | 안 막힘 | 강제 종료와 같아요 | 위와 같음 |
| 최근 앱 화면에서 밀어서 닫기 | 막힘 | 순정, 삼성에서는 예약이 남아요. 일부 중국 제조사는 강제 종료처럼 동작해요 | 샤오미 등은 '잠금(자물쇠)' 안내 |
| 방해 금지 모드(알람 허용 켜짐, 기본값) | 막힘 | `USAGE_ALARM` 소리는 방해 금지에서도 나요 | 없음 |
| 방해 금지 모드(알람 허용 꺼짐, '완전 무음') | 안 막힘 | 알람 소리 통로까지 막혀요. 채널의 `setBypassDnd`는 알림 소리에만 듣고, 앱이 직접 트는 소리는 못 살려요 | 알람을 켤 때와 전날 밤에 방해 금지 설정을 읽어(`getCurrentInterruptionFilter`, 정책의 알람 허용) 막혀 있으면 경고. 방해 금지 접근 권한이 있으니 울릴 때만 잠깐 '알람만 허용'으로 바꾸는 방법도 있지만 사용자 설정을 건드리는 일이라 기획 결정 필요 |
| 삼성 '모드와 루틴'의 수면 모드 | 일부 | 수면 모드는 방해 금지를 켜요. 기본은 알람 허용이지만 사용자가 끌 수 있어요 | 위 방해 금지 경고와 같음 |
| 삼성 루틴으로 무음, 방해 금지, 절전 켜기 | 일부 | 무음은 상관없고(알람 통로), 방해 금지는 위와 같고, 절전은 아래와 같아요 | 위 대책으로 충분 |
| 삼성 루틴의 '앱 닫기' 같은 동작 | 일부 | 강제 종료처럼 동작하면 예약이 지워져요(삼성 버전마다 달라 확인 필요) | 강제 종료와 같은 흔적 알리기 |
| 절전 모드(일반) | 막힘 | `setAlarmClock`은 절전 모드에서도 울려요 | 없음 |
| 삼성 최대 절전 모드 | 안 막힘 | 허용한 앱 몇 개만 돌아요 | 도움말 안내. 켜져 있는지 알아채기는 어려워요 |
| 사용자가 배터리를 '제한'으로 둠 | 일부 | 백그라운드 실행이 막혀 서비스가 못 뜰 수 있어요 | `isBackgroundRestricted` 검사를 권한 화면에 추가(배터리 줄과 묶어서) |
| 알람 볼륨 0 | 일부 | 앱을 열 때만 검사해요. 그 뒤 사용자가 0으로 내리면 소리 없이 진동만 나요 | 울리기 직전에 알람 볼륨이 0이면 최소 크기로 올리기(대부분의 알람 앱이 함) |
| 통화 중 | 일부 | 통화 중에는 소리가 작게 나거나 막힐 수 있어요(안드로이드 기본 동작) | 받아들임. 놓친 알람 알림으로 충분 |

### 2-5. 구글 플레이 심사 위험 (기기 문제는 아니지만 출시를 막을 수 있음)

| 권한 | 위험 | 할 일 |
|---|---|---|
| `USE_EXACT_ALARM` | 중간 | 알람, 캘린더 앱만 허용돼요. 플레이 콘솔에서 '알람 앱'이라고 신고 |
| `USE_FULL_SCREEN_INTENT` | 중간 | 14부터 알람, 전화 앱만 자동 허용. 콘솔 신고 필요 |

| `SYSTEM_ALERT_WINDOW` | 낮음 | 쓰는 이유를 설명할 수 있으면 됨 |
| `ACCESS_COARSE_LOCATION` | 낮음 | 개인정보 처리방침에 날씨용이라고 적기(초안 있음) |

## 3. 기기 없이 시험하는 방법

| 방법 | 비용 | 무엇을 확인 | 한계 |
|---|---|---|---|
| 안드로이드 에뮬레이터(Android Studio) | 무료 | 버전별(8, 10, 12, 13, 14, 15, 16) 권한 흐름, 재부팅, 시간 변경 | 삼성, 샤오미 배터리 관리는 재현 안 됨 |
| adb로 절전(도즈) 강제 | 무료 | `adb shell dumpsys deviceidle force-idle` 뒤 알람이 울리는지 | 순정 동작만 |
| adb로 앱 대기 상태 강제 | 무료 | `adb shell am set-standby-bucket <패키지> restricted` 뒤 울리는지 | 순정 동작만 |
| adb로 배터리 '제한' 흉내 | 무료 | `adb shell cmd appops set <패키지> RUN_ANY_IN_BACKGROUND ignore` | 순정 동작만 |
| adb로 강제 종료 | 무료 | `adb shell am force-stop <패키지>` 뒤 예약이 사라지는지, 앱을 열면 다시 잡히는지 | |
| adb로 재부팅, 시각 변경 | 무료 | `adb reboot`, 설정에서 자동 시간 끄고 바꾸기 | |
| adb로 다음 예약 확인 | 무료 | `adb shell dumpsys alarm` 에서 앱 이름을 찾아 예약이 남았는지 | |
| 파이어베이스 Test Lab | 무료 범위 있음(실기기 하루 5회 정도, 가상 기기 10회 정도) | 여러 실제 기기(삼성 포함)에서 앱이 켜지고 화면이 깨지지 않는지 | 알람이 몇 시간 뒤 울리는지 같은 긴 시험은 어려움 |
| 삼성 원격 시험실(Remote Test Lab) | 무료(삼성 계정) | 실제 삼성 폰을 인터넷으로 빌려 원 UI 설정과 권한 화면 확인 | 한 번에 짧게만, 밤새 시험은 안 됨 |
| 플레이 비공개 테스트(내부 테스트) | 무료 | 지인 폰에서 실제로 며칠 써 보기 | 사람을 모아야 해요. 지금은 개인 개발자 계정이면 출시 전 비공개 테스트(12명, 14일) 조건도 있어요 |
| 앱 안 진단 기록 | 무료(이미 있음) | `AlarmDiagnostics`가 예약, 대신 예약, 서비스 실패를 남겨요 | 사용자가 보내 줘야 볼 수 있어요. '문제 보내기' 버튼으로 기록을 메일에 붙이면 좋아요 |

이미 정리된 시험 목록: `docs/test-alarm-cases.md`. 위 adb 명령을 그 목록에 붙이면 에뮬레이터에서 한 번에 돌릴 수 있어요.

## 4. 우선순위 (혼자 하는 개발 기준)

### 첫 버전 전에 꼭 할 것

| 순서 | 할 일 | 크기 | 이유 |
|---|---|---|---|
| 1 | 방해 금지에서 알람이 막혔는지 검사해 경고(설정 '권한' 화면 줄, 전날 밤 확인 알림에 함께) | 작음 | 삼성 수면 모드 사용자가 많고, 막히면 소리가 0이에요 |
| 2 | 울리기 직전 알람 볼륨이 0이면 최소 크기로 올리기 | 작음 | 앱을 연 뒤 볼륨을 내리면 지금은 못 막아요 |
| 3 | 강제 종료 흔적 알리기: 앱을 열 때 '예약이 지워져 있었음'을 알아채면 한 번 알리고, 온보딩이나 도움말에 '강제 종료하면 안 울려요' 한 줄 | 작음 | 앱이 막을 수 없는 가장 큰 구멍이라 알리기라도 해야 해요 |
| 4 | 배터리 '제한' 상태(`isBackgroundRestricted`)도 배터리 줄에서 함께 검사 | 아주 작음 | 검사 한 줄이면 돼요 |
| 5 | 플레이 콘솔 신고 준비: 알람 앱 신고, 앞 서비스 종류 설명 영상, 접근성 서비스는 첫 버전에서 빼는 결정 | 문서 작업 | 심사에서 막히면 출시가 늦어져요 |

### 나중에 해도 될 것

| 할 일 | 이유 |
|---|---|
| 샤오미, 오포, 비보 '자동 실행' 설정 안내 줄 | 한국 점유율이 낮아요. 사용자 의견이 오면 |
| 진단 기록 '문제 보내기' 버튼 | 사용자가 생기면 원인 찾기에 필요해요 |
| 방해 금지를 울릴 때만 잠깐 바꾸기 | 사용자 설정을 건드리는 일이라 기획 결정이 먼저예요 |
| 삼성 최대 절전 모드 안내 | 쓰는 사람이 적어요. 도움말에 한 줄이면 충분 |
| 에뮬레이터 버전별 자동 시험 | 첫 버전 뒤 업데이트가 잦아지면 |
